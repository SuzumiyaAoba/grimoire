# ローカル・RAG アプリケーションの比較

[調査トップ](../README.md) / [横断比較](index.mdx) / [既存の文書検索・RAG 基盤](../systems/retrieval-landscape.md)

確認日: 2026-09-29。主比較は AnythingLLM、Open WebUI、Khoj、Kotaemon、FastGPT、MaxKB、QAnything、DocsGPT、Open Notebook の9系統。Quivr は現行 repository と旧アプリ資料の継続性を確認できなかったため、補足候補として分けた。既存調査で詳しく扱った Dify Knowledge、Onyx、RAGFlow だけでは薄かった、ローカル文書チャット、個人用セカンドブレイン、引用確認、workspace とユーザーの境界を補う候補として選んだ。

公式ドキュメント、公式 README、必要な箇所では公式 API 定義を読んだ。製品をインストール・実行しておらず、ライセンス適合、性能、運用保証は評価していない。製品の機能説明と、今回確認できなかった挙動を分けて記載する。特にファイルやチャンクを削除できる API があっても、履歴・引用・派生索引のすべてが消える保証とは解釈しない。

## 補足候補: Quivr

現在の `QuivrHQ/quivr` は `The-Vibe-Company/quivr` へ移動し、README は利用者向け既存アプリより開発者向けの RAG core と説明する。PDF / TXT / Markdown 等と独自 parser の説明はあるが、利用者・workspace のモデル、citation の位置表示、現行の文書置換・削除・同期は確認できなかった。[D-R2-A-QUIVR-README] 旧 Quivr docs は現行 repository との継続性を確認できないため、現行機能の根拠に使わず補足保留とする。[D-R2-A-QUIVR-OLD-DOCS]

## 既存の Dify・Onyx・RAGFlow と比べた位置

既存比較では、RAGFlow は文書解析・chunk 管理・citation をまとめる self-host RAG engine、Dify Knowledge は app / workflow に組み込む knowledge base、Onyx は社内アプリを connector で横断する検索・assistant として整理されている。[既存の文書検索・RAG 比較](../systems/retrieval-landscape.md)

- **ローカル文書チャットと workspace 分離:** AnythingLLM と Open WebUI が補う。文書を使う会話 UI の選択肢であり、Onyx の connector 横断や permission sync を置き換えるものではない。[D-R2-A-ANYTHING-DOCS] [D-R2-A-OPENWEBUI-KNOWLEDGE]
- **個人の文書・ノート検索:** Khoj と Open Notebook が補う。利用者の notes / research notebook を中心にし、共有 knowledge base の ACL を前提とする製品とは管理単位が異なる。[D-R2-A-KHOJ-README] [D-R2-A-OPENNOTEBOOK-SOURCES]
- **引用を元資料へ戻して確認する操作:** Kotaemon、FastGPT、Open Notebook は PDF highlight、chunk reader、source passage のいずれかを明示する。引用表示があるだけで主張の正しさや更新履歴まで証明するわけではない。[D-R2-A-KOTAEMON-USAGE] [D-R2-A-FASTGPT-CITATIONS] [D-R2-A-OPENNOTEBOOK-CITATIONS]
- **同期・削除の境界:** Open WebUI の directory sync と MaxKB の website sync は差分や全置換を明記する。FastGPT、DocsGPT、QAnything は API で source / chunk の更新・削除を扱う。API の CRUD が、旧 revision、chat history、backup からの完全消去を保証するかは別途確認が必要である。[D-R2-A-OPENWEBUI-KNOWLEDGE] [D-R2-A-MAXKB-KNOWLEDGE] [D-R2-A-FASTGPT-DATASET] [D-R2-A-DOCSGPT-SCOPES] [D-R2-A-QANYTHING-API]
- **主張の訂正:** 今回読んだ資料の中心は文書と chunk の管理である。chunk 編集や文書再取り込みができても、旧主張を訂正として保持し、根拠・有効期間・変更理由を検索できるとは確認できなかった。今回の設計ではこの層を RAG アプリの更新機能と分けて比較する。

## 初期スコープへの使い分け

原資料の版と位置を確かめる評価では、Kotaemon、FastGPT、Open Notebook を候補に置く。ローカル利用・文書の再利用・検索範囲の指定を確かめる場合は Open WebUI と AnythingLLM を加える。team / workflow を含める場合は FastGPT と MaxKB、agent が参照する source を API で管理する場合は DocsGPT を比較する。Khoj は個人用記憶と複数 client 同期、QAnything は offline QA の比較点として使える。Quivr は現行の利用者向け運用説明が不足しているため、現段階では監視候補に留める。

比較実験では、同じ原資料・モデル・質問・権限条件で、引用箇所の正確さ、更新後に古い内容が検索されないか、削除後に source / chunk / citation が残るか、手作業と費用を別々に測る。各製品についてこの調査で未確認とした項目を、そのまま製品の機能欠如とは解釈しない。
